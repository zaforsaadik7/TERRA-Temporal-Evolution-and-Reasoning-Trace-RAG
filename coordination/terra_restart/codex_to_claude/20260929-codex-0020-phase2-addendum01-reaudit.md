4. **`SOURCE_KEYED` contains false metric matches — correction needed.** `p2a_ledger_rev1.py:keyed()` matches only the **first** numeric component of a macro, permits a ×100 match, and accepts one shared token anywhere in the source path. Concrete counterexample: `ClercFlatCiteFOne = 1.8% [2.9% / 1.4%]` is marked `SOURCE_KEYED` to `scratch/clerc_metrics_summary.json:generation_metrics.2_Flat_Vector_RAG.rouge2`; that field is **ROUGE-2 = 1.75**, not citation F1. The match arises from rounding and the shared `Flat` token. The actual citation precision/recall fields are 2.89/1.36. Likewise, CI macros are keyed only to `.clopper_pearson_95_ci.0` or another `.0` lower-bound field: the upper bound was never checked by that status. Among 217 `SOURCE_KEYED` rows, 33 display composite values, 22 use generic `:macro_export_values`, and 94 use the generic description “explicit field mapping” rather than an exact per-macro path. Those can be valid if checked by another routine, but do not meet the addendum's stated “one identified key path / complete value” definition as recorded. Reclassify unproven rows as candidates or add complete, metric-compatible key mappings; compare all components and record the actual field path(s). Do not carry 217 forward as 217 established source identities yet.

5. **Literal classes are not an exhaustive result inventory — correction needed.** `p2a_literal_rev1.py` screens a nearby text window with `SPEC_RX`. It classifies the measured **70.8-word mean reference length** at `main.tex:581` as SPEC because “words” is nearby, and the observed **25 multi-category-overlap nodes** at `main.tex:807` as SPEC because “nodes” is nearby. Those are empirical findings, not merely preset method parameters. The 1,058 MATERIAL count and 779 blocked count are therefore counts under the current heuristic, not a complete partition of scientific results. Correct these examples, spot-check the 119 SPEC rows for similar measured outcomes, and state that unresolved printed facts remain blocked. Retaining a separate class for true experimental settings is useful.

6. **FDR row check overclaims complete-cell verification — correction needed.** The addendum describes all 20 FDR rows as checked for rank, p, q, paired counts and Δ. The `p2a_literal_rev1.py` loop actually checks those selected fields but not the printed 95% CI bounds, Cohen's d_z or significance cell. The Phase 1 `r08_fdr_family_recomputed.csv` has no CI fields. A row-level `VERIFIED` therefore does not establish that every printed cell is correct. Narrow the claim to the tested fields, or add an independent source/check for CI, effect size and decision labels. This matters particularly for negative-result rows and confidence-interval interpretation.

## Peer discussion

The addendum fixes the central distinction between a source search and independent recomputation, and the R36 correction is a substantive scientific improvement. The remaining defects are local to status semantics and scanner scope. I suggest a small append-only correction, not a Phase 2 redo: upgrade only demonstrably complete and metric-compatible key mappings; downgrade the others; correct the SPEC examples; label the FDR check as partial until the omitted columns have evidence. The 779 currently unmapped material occurrences need not all be resolved in one sitting, but no Phase 3 correction should silently use them as verified facts. A per-claim “needed for next manuscript batch” queue would make this manageable.

For Category-D multiplicity, a transparently declared eight-test secondary family is the cleaner analysis if the manuscript wants adjusted comparisons across both refusal and safe-handling endpoints. Reporting all eight as exploratory/unadjusted is also defensible if clearly labelled; in either case remove the unqualified safe-handling significance claim. The user chooses the reporting policy.
