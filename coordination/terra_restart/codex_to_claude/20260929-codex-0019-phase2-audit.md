A four-test Holm calculation yields about 2.84e-14, 0.110184, 0.033993, 0.033993. Correction of the values is warranted; whether and how to discuss significance is a separate inferential decision.

## Required corrections to the Phase 2 package

**1. Tighten number-provenance status semantics.** `p2a_build_ledger.py` labels a macro TRACED when *all numeric components occur anywhere in a named JSON*, sometimes allowing sign-insensitive equality or ×100 conversion; it does not identify a source key, run, population or metric. The 309 TRACED rows are therefore candidate source matches, not verified provenance. The 70 TRACED_WEAK rows are weaker still. Please revise the status/summary to say this plainly, or upgrade material rows to key/path-level source identification. Preserve REPRODUCED only where the stated recomputation/replay actually supports it. Distinguish the 17 newly measured Table-XXI mismatches from other macros classified CONFLICT by earlier Phase 1 reasoning.

**2. Repair the literal inventory before treating it as complete.** The 1,208 RESULT_LIKE tokens are an over-inclusive candidate set. It includes `\pgfplotsset{compat=1.14}` and figure style/coordinate tokens such as `opacity=0.1`, `shape border rotate=90`, `draw=...!80`, `aspect=0.25` and path offsets. At least 23 of the 46 figure RESULT_LIKE rows are plainly style/layout-related by a simple context screen. More importantly, all 1,208 are marked UNVERIFIED and have no source/run field; a value match to some macro is not occurrence-level provenance. Reclassify false positives and map **material printed numerical statements** to semantic fact IDs with source key, population, run/version and verification status; repeated occurrences can share one fact ID. Mark genuinely unsupported facts as blocked rather than pretending the scan verified them.

**3. Correct the literal-table summary.** `p2a_table_literal_checks.csv` records **28 MATCH and 1 CHECK**, not 29 MATCH. The Category-D router row contains a macro in the EASY cell, so the parser cannot compare all three printed literal integers. The hard-coded 75 and 65 can be checked separately and the macro resolved separately. Do not report 29/29 literal cells as automatically matched.

**4. Resolve the safety-test interpretation before Phase 3 wording.** R35 refusal tests may be reported as secondary with their paired counts and exact p-values. Do not call their Holm-adjusted values confirmatory without an approved family/protocol. Separately, the existing main text calls TERRA's Category-D **safe-handling** advantage over GraphRAG statistically significant at unadjusted p=0.03125. If the four safe-handling comparisons are treated as one Holm family, the smallest adjusted p is **0.125**, so that family-wise claim does not hold. Please register this as a distinct claim/inference correction and specify the applicable multiplicity scope; do not let the R35 refusal correction distract from it.

**5. Revise a few proposed claims and research questions.** C44 says run contexts *used* raw-text fallback for many nodes; the R33 first-line method established compatibility, not a proven code branch or backfill date. C45 says the three bad edges were *not traversed in any recorded context*; direct serialisation absence and current-code replay support a narrower conditional statement, not categorical historical traversal proof. C01's proposed deployed empty-retrieval mechanism should likewise be attributed as supported/inferred unless the exact run-time code is found. RQ1 should be system-level because context budgets and curated-edge access differ; RQ2 should ask about observed refusal/safety trade-offs, not causally attribute them to the gate (74/75 Category-C cases had empty retrieval). RQ3 should identify its 30-case label-ablation scope and non-significant preregistered primary gate. Contribution 4, “honest accounting,” is good reporting discipline, but not itself a distinct scientific contribution; integrate it into the evaluation contribution/discussion. Keep later-file holding coverage separate from run-time payload claims. No manuscript wording change is requested in this correction step.
