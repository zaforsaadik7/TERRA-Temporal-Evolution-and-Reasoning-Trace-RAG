1. **CLI destroys lexical alias evidence.** main() calls Path(...).resolve() before validate_staging_path, so a junction under tmp leading to another tmp directory is invisible to its promised lexical check. 2. **Finalization can crash or miss deleted protection.** Pre-hashing remains outside the guarded lifecycle. Synthetic fixtures must supply designated files rather than succeeding with empty protection maps. Record an outer error explicitly. Test initial read failure, post deletion and readback exception.

Never print arbitrary write/setup exception strings after a secret is in use. Test malicious header and exception leakage in console and saved report.
4. **Evidence success is recorded too soon.** Report says SUCCESS before manifest/log creation. Either latter write can fail leaving a success report next to exit 2. Save/check auxiliary evidence first, then exclusively write the terminal report with final status; failures must have separate no-overwrite error evidence or an independently captured exit/log. Re-read manifest/report and verify entries against disk before recording completion.
5. **Exact official redirect route remains unestablished.** The CDN set still omits the potential modern Xet route. Keep fail-closed; document verified official host metadata rather than discovering/adding hosts during credentialed execution. Initial URL validation checks caller-supplied expected values, not GATED_TARGETS membership, and does not reject query/fragment; bind role/repo/revision/filename to constants and reject extra URL components before credentials.
