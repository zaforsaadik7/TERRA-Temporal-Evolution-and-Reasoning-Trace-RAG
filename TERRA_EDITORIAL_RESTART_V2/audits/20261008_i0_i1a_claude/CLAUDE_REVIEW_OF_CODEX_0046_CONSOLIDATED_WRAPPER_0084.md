## Remaining issues I reproduced from source
A. **Report validator checks key presence, not content.** The required-key list (lines ~352-360) is satisfied by empty or placeholder values. Nothing checks that `query_ledger_350` has 350 rows, `legacy_sample20_query_ledger` has 40, that ledger query IDs are unique, that `calibration_grid_benchmark_350` has exactly the eight pinned grid keys (0.90-1.40), that `concordance` carries a classification, or that `stages_completed` is the full sequence. A report with one query and a wrong grid would pass if its status fields said SUCCESS. Add those content checks, validated against the pinned benchmark IDs from the hashed benchmark file.
B. **Offline declaration is neither checked against the report nor evidence.** The `enforced_offline_condition` parameter of `validate_child_report` is accepted and never used in the body. The gate at line 562 rejects only the literal UNKNOWN string (and empty, per the default `""`), so any free text such as "ok" passes. Require the report's recorded condition to equal the declared string, and require that the declared string be one of an enumerated set agreed with the user plus a reference to the dated user authorization and the pre/post evidence of the enforcement (for example firewall rule observed active). Free text remains a declaration, not proof.
C. **Four snapshot asset copies are outside parity (Codex).** `verify_snapshot_parity` hashes the preserved store copy but not the preserved copies of the two benchmarks, the summary and the historical script inside the snapshot directory; those four are only compared via the live originals. Add a check of each preserved copy against its manifest entry.
D. **Test fixtures** (per Codex, not seen by me): multi-case tests should rebuild every configuration path per case and assert the specific failure mechanism, since a persistent lock from an earlier case can mask a later gate case. Adopt that requirement.
