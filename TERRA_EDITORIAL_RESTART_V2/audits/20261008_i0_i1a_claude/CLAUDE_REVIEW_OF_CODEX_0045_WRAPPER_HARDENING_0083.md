## Blockers I reproduced
1. **Mock check is vacuous (Codex #3).** Line 589 reads `rep_data.get("is_mock_override", False)` at the report's top level. In the production report that key exists only at `metadata.embedding_function_delegate.is_mock_override` (diagnostic lines ~788 and 1037), so the wrapper always sees the default False and the check can never fail. Also, that field is `is_mock_allowed and not (genuine EF)`, so a run using query or writer mocks with a genuine embedder reports False. The production report records no list of active `mock_overrides`. Fix in the wrapper: require the nested field to be present and False (absent = failure), require `report["script"]["sha256"]` to equal the pinned diagnostic hash, require the report's run ID to equal the discovered child folder, and confirm that the launched argv contained only the three approved options (the CLI has no mock path). Test with a production-shaped fixture copied from a real report schema, not a hand-written one.
2. **Failure records can still disagree with the exit code (Codex #1).** Order in the `finally`: wrapper exit code is computed (lines ~688-691) and returned, and only then is `exit_code.txt` written. A failure writing it appends a reason (line ~697) but the code stays 0, and metadata then shows `success: true` next to non-empty `failure_reasons`. `file_sha256(console_log_path)` and the discovered-report hash are unguarded and can raise inside `finally`, losing the metadata. Metadata is opened with `"w"`, not exclusive `"x"`. The wrapper's own stdout summary can fail too. Fix: compute final status after every evidence write and every hash read, wrap each in its own try, and make any failure force a nonzero code and `success:false`; write metadata exclusively; if metadata cannot be written, emit a stderr terminal record.
3. **Post-run store check can silently skip (Codex #2).** If the snapshot manifest cannot be read, `expected_store = {}` (lines ~620-622), the loop does nothing, and `post_hash_passed` stays True. Extra or unexpected files in the store directory are never looked for, only listed manifest paths are hashed. Fix: failure to load the manifest is a failure; compare the full directory file set to the manifest (extras and missing both fail); require exactly the 11 store files.
4. **Lock is burned by pre-launch gate failures (Codex's blocked second parity case).** The never-deleted lock is acquired at step 2, before the pin and parity gates (steps 3-4). Any gate failure after that point permanently blocks the single approved run. Fix: acquire the lock immediately before `Popen`, after all gates pass; if a failure happens after the lock but before launch, record it in a lock-state file rather than leaving an unexplained lock.
