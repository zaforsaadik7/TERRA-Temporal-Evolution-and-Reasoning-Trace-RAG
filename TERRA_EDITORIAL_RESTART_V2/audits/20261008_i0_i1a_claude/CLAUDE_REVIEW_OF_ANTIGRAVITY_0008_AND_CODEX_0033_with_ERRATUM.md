1. **The proposal is nearly a copy of the original generator's calibration step** (same `get_collection`, same `coll.query(query_texts=all_texts, n_results=1)`, same cohorts, same `d >= tau` counts, and `query_id`/`category`/`query` keys that exist in the benchmark; 350 unique IDs). 2. **Pre-register interpretation before any run.** (a) Exact match of all eight rows and AUROC: label as "contemporary reproduction of the saved aggregate grid", and the exact in-domain maximum then lies in [1.20, 1.25) on current assets. (b) Partial match: report all differences; the table remains unsupported as a historical claim and any manuscript correction must say so. (c) Large mismatch: no replacement without a new approved decision. Decide the tolerance for AUROC (the saved value is 0.9901333...; an exact tie-corrected computation should match to float precision if the data match).
3. **Do not fail on tiny negative squared distances.** HNSW squared-L2 for near-identical vectors can come back slightly below 0 from float error; Codex's "finite and nonnegative" check should record such rows and clamp only in the derived `euclidean_distance_sqrt` field, not abort or alter the raw value.

Also record the six ONNX cache file hashes, not only three.
5. **Preserve the AUROC implementation:** hash the original `compute_auroc` function text and compare with the new one (tie handling 0.5), instead of assuming equal behaviour.
6. **Keep the output filename check** (refuse to overwrite) and write a failure report, as Codex requires. The proposal hard-codes a Windows user cache path; make it a validated argument, not a silent default.
