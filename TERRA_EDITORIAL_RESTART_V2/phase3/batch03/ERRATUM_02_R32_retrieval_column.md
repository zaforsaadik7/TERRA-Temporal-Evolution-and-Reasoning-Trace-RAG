# Erratum 02 (Claude): the Table XXI retrieval column is not a "pure read" of the v2 timing fields

- **Date:** 2026-10-05. **Append-only note:** it does not edit any earlier file. It qualifies one recommendation in `evidence/phase1/R31/R31_R32_R19_R13_NOTES.md` (R32) and the Phase 1 register row R32.
- **What the earlier note said:** the Table XXI decoupled columns have "no v2 source" (overall retrieval 187.5 ms against a v2 value of 1,536.6 ms) and should be regenerated "from v2 telemetry (a pure read of `timing`)".
- **What the data show (found while drafting Batch 03):** for the 240 hard-route rows the logged `retrieval_ms` is cumulative and includes `routing_ms` (correlation 0.9988; the difference is always between 178 and 1,230 ms). The raw mean of 1,536.6 ms therefore is not a retrieval time. The paper's old retrieval values for Categories B, C and D (293.9, 249.9 and 233.2 ms) **are** route-aware v2 values (logged retrieval minus routing). The values that really were wrong are Category A retrieval (0.0 ms, against 353.4 ms), the overall retrieval (187.5, against 288.5), and the NLI values for Categories A, C and D, which had been derived as residuals instead of using the logged grading time.
- **Effect:** Batch 03 uses the route-aware retrieval definition and the logged grading time, and reports the unattributed remainder explicitly. The R32 finding itself (the fast path runs retrieval and NLI grading) is unchanged and is supported by the telemetry.
