## Blocking findings

1. **Fixture schema hides incompatible corpus extraction.** Tests create embeddings(id TEXT, collection_id, document). Installed Chroma migration 00001-embedding-metadata.sqlite.sql instead defines integer id, segment_id and embedding_id, with document metadata stored separately. Reader selects id preferentially and guesses document/text columns, or reads every embedding without collection filtering when collection_id absent. This can fail on authentic schema or misidentify IDs/cross collections. Use native collection.get from the validated disposable client or a explicitly versioned schema-aware join for external embedding IDs/document metadata/collection segments. Build authentic-shaped synthetic fixtures with multiple collections, integer internal IDs, distinct external IDs and metadata; reject duplicates/empty/non-string documents instead of overwriting dictionary entries. No real store inspection is required for this repair.

2. **Metric/cache validation is fail-open.** validate_store_schema starts metric=l2, suppresses JSON errors and searches only guessed top-level/metadata keys. Absent/malformed/unrecognized schema is therefore certified l2. Query/client access does not require schema verification, and default get_client imports a real PersistentClient with default embedding/downloader behavior. Keep adapter runtime blocked without explicit reviewed client/embedding configuration; require successful collection dimension/metric validation before corpus/query operations, exact cached embedding binding and download guards. Real adapters may remain unavailable during Stage 1. Do not treat a named factory as proof of configuration.

3. **Missing query distances fabricated.** Independent synthetic client returns ids [['z','a']] with no distances. query_dense_candidates accepts them, assigns zeros, and returns [['a','z']]. Reject missing distances, wrong batch shapes, null/non-string IDs, boolean/nonfinite distances, too many candidates, unknown IDs and malformed input text before yielding rankings. Preserve recorded native distances, specify tiny negative floating-point tolerance if needed rather than claiming Euclidean values. Test exact failures using the production reader method.

4. **Receipt parity is inconsistent and not freshly enforced.** issue_isolation_receipt hashes a caller-provided manifest without validating source/snapshot/disposable parity. Validation then excludes WAL/SHM/lock files although issuance includes them; a legitimate complete baseline can fail, and newly added files of those names can bypass the pre-client full-inventory check. Use full manifests at issuance and before first client binding, validate all three lifecycle identities/parity and reject substituted receipts. Distinguish authorized copied-store operational changes after binding from before-binding tampering. Revalidate path/receipt immediately before opening, not only in constructor. Do not claim cryptographic authenticity solely from dataclass type or random receipt ID.

## Graph-loader limitation

Either truthfully name it an in-memory no-uncompressed-disk loader with explicit decompressed byte/resource limits, or implement bounded streaming.
