# Compact manifest transport and explicit approval binding

Date: 23 October 2026. Codex implementation self-verification, not independent peer certification. User explicitly approved code and synthetic tests only (`yes I do`). No execution permission follows.

## Source changes

Five runtime files (including the new offline_smoke_manifests.py) and four test files are identified in manifest.json with byte-preserved .final copies. Existing-file .before snapshots, source.diff and new_files.diff preserve the change boundary. Extra unchanged before-checkpoints are retained. All prior inventories, candidate packets, source datasets and peer messages remain untouched; the old source inventory is now historical and must be refreshed after acceptance.

1. FrozenFilePinVerifier accepts independently pinned manifest specifications. Production declared_files entries may include `members` with exactly roots, count and complete_roots. Config/request/context pins contain the manifest digests rather than every expanded member digest. Both production parent and child call the same verifier; child verification is not waived by a parent receipt. The existing packet/request/context caps remain unchanged.
2. Manifest bytes are bounded to 16 MiB each, at most 64 manifests, 50,000 rows each and 100,000 total rows before expansion. Manifest size/hash, stable read metadata, JSON duplicate fields, schemas, row counts, digest/size types and explicit absolute root containment are checked. Paths with traversal, stream syntax, symlinks or reparse points fail. Duplicate rows within a manifest and conflicting identities across manifests fail. Identical overlapping identities across separately pinned manifests are deduplicated and byte-checked once per verify call.
3. Every expanded member gets the same actual file existence/size/stability/SHA-256 checks as a direct constituent. A manifest-file hash alone is never accepted as member verification. Required production runtime/source paths must be in the successfully verified expanded path set. Verification failure clears that set and prevents authority/dependency admission.
4. complete_roots is explicit. For a complete runtime/cache/store tree, declare that root there; unexpected/missing files then fail membership checks. For selected code/artifact lists it may be empty, but that does NOT certify absence of extra files. Actual packet review must choose complete-tree coverage for full-tree inventories and cannot silently downgrade them. Grouping excluded subtrees (such as base Lib/site-packages) needs an explicit reviewed root partition; this repair does not infer exclusions.
5. SmokeLaunchConfig adds controller_policy, restricted to ONLY_VERIFIED_OWN_DIRECT_PARENT_ACCEPTED_NO_NETWORK_EXEMPTION. Production requires an explicit separately reviewed policy value. verify_approval_bytes now requires firewall_program and controller_policy, compares them to reviewed config/constant policy, and rejects old/missing-field records and mismatches. No historical approval was rewritten or accepted. No decision-manifest-hash alternative was added; explicit fields implement the reviewed bounded choice.
