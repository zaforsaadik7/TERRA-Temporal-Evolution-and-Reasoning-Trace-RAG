# Candidate smoke packet review criteria

Scope: one benchmark query, two hypothetical EASY/HARD envelopes, authentic local retrieval/embedding/token counting only. This is not the 350-query preflight and not a new answer-generation or legal-accuracy experiment.

The packet proposal is intentionally non-executable: no query identity or execution approval is invented. Its proposed 300-second / 4 GiB / 16 MiB ceilings require review and user acceptance. A bounded operational stop is not a successful feasibility result.

Before forming a real executable packet:

1. Obtain permission to inspect benchmark query IDs/category labels/text and select a deterministic smoke query. Recommended: first Category B record in file order, without using gold answers or performance results to select it. Save the exact ID and UTF-8 text hash. This is input selection, not a retrieval/model run.
2. Verify refreshed inventory output and its generator. The broad installed environment includes unused packages and is not a claim all of them are imported. AST traversal cannot discover every dynamic import; OS libraries and runtime-dispatched DLLs remain an explicit closure limitation. Inspect startup `.pth` behavior and import-path assumptions against the venv configuration.
3. Review actual native code and complete source changes including the earlier native-schema metric repair. Peer-0195 covers the runtime-image revision, not automatically every earlier schema repair.
4. Check all proposed output/copy/lock paths remain absent, no source journals appear, full source/cache inventories still match, and no conflicting active work exists immediately before launch. These checks do not lock the source.
5. Bind the real execution approval to the final exact command, query, resource limits and rule/process policy. Keep both parent and child under the target image's outbound block; stop for any other known matching process, record unreadable processes as uncertainty.
6. Review the authentic packet and its SHA-256, then the separately hashed root anchor/admission changes. An authorization-bound packet cannot be finalized by substituting nulls or a fake approval digest now.

Proposed smoke pass requires: elevation/service/profiles/rule-property checks; verified owned-controller identity; no extra known matching process; source/snapshot/copy parity; authentic child image match before dependencies; 20,000 shared corpus/graph IDs; finite bounded native dense retrieval; both hypothetical role envelopes passing; child and wrapper zero exit; confirmed Job-tree termination; preserved bounded capture/report; successful source/cache/snapshot and pinned-file postchecks; ownership-only verified firewall removal; and final evidence outcome written after transcript closure. Failure at any required step is a failed attempt, not permission to retry.

A successful smoke outcome would establish feasibility only for this input and this local configuration. It would not certify the provider context window, actual router decisions, generated answer quality, legal correctness, the full benchmark, historical numbers, firewall effectiveness beyond observed checks, or manuscript changes. All results retain provisional role ceilings and synthetic judge-answer caveats.

No Databricks or Hugging Face key is needed for this stage. No credential-file inspection is authorized or performed.
