\section{Prospective controlled hybrid comparison}
\label{supp:matched-comparison}
This fresh run is distinct from the canonical five-system evaluation and the earlier partial attempt. All 350 assigned queries (100 A, 100 B, 75 C, 75 D) completed. H used native dense top-100 and Okapi BM25 top-100 candidates fused with reciprocal-rank constant 60; T used the same dense ranks, two seeds, depth zero/two nodes for EASY and depth two/up to 40 nodes for HARD, with incoming/outgoing hub caps 75/25. Layer-1 stored document text was identical across sparse and dense indexing, while Layer-2 evidence fields came from one shared 20,000-node graph snapshot with 145,363 edges (145,310 citations and 53 overruling relations). This corrected snapshot is not an identity claim about the historical 56-tag graph.

One query-only router selected EASY/HARD for both arms; this control did not exercise the legacy title-match or geometric-proximity helper and is not a replay of the historical routing implementation. The arms shared the formatter, 6,000-token evidence budget and 7,000-token generator/verifier prompt ceiling; judges allowed 15,000 local input tokens, including the actual answer. Generator/verifier output caps were 4,096/512; judge caps were 1,024/4,096, with low GPT-OSS reasoning effort. The same role-specific JSON schemas constrained router, verifier and judges in both arms, with plain-text generation. No malformed output was repaired. A negative verifier decision produced a standardized refusal that both judges assessed. Generation temperature was zero, with hash-seeded arm order (seed 42); this does not establish provider determinism.

Serving endpoints were Databricks Gemma 3 12B (router), Llama 3.3 70B (verifier/generator), Qwen3-Next 80B A3B and GPT-OSS 120B (judges). The archived packet and raw returned identifiers bind this run; identifiers do not certify server weights or tokenizer equivalence. The recovered Gemma tokenizer retains its unresolved independent upstream transport-receipt caveat. Provider-reported token usage was checked and settled for every request.

Among the 100 assessable Category~B pairs out of 100 assigned, the T-minus-H composite difference was $0.2689$ (paired percentile-bootstrap 95\% CI $[0.1603, 0.3720]$; two-sided paired randomization $p=0.000010$). The primary Category~B analysis uses 10,000 query-level paired bootstrap resamples and 100,000 paired sign-flip draws (exact enumeration if at most 14 pairs are assessable), seed 42. It is separate from the historical multiple-testing family. Complete-case inference is conditional on assessability and can be biased by missingness. The assigned Category~B cohort's worst-case difference bounds are $[0.2689, 0.2689]$, allowing each excluded pair to range from -1 to 1. Faithfulness concerns support in supplied evidence, not independent legal correctness or task utility; justified abstentions and substantive answers must be interpreted with their separate outcomes.

A prior unstructured-output attempt stopped on invalid JSON after 83 Category~A pairs and 671 settled calls; those pairs are not resumed or merged here. A subsequent diagnostic stopped before any provider call because of a local zero-wait timing bug. Its repair was tested before a fresh five-role compatibility probe and this independent run. This fresh study used 2706 settled requests and had a conditional reference token cost of \$61.935583. The conversion assumes the disclosed, unverified USD-per-DBU rate and is not an invoice; fixed charges and credits were not independently certified. No HTTP retries or silent query replacement occurred. Raw journals, frozen inputs and the analysis ledger preserve the complete history. The comparison does not validate historical adapted-baseline implementations, isolate every graph/scaffold component, establish cross-seed stability or replace licensed-practitioner review.
